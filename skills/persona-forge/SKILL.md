# Persona Forge · 人格化引擎

> 「写不进去的那部分，才是你真正的护城河。」——但写得进去的部分，已经足够强大。

## 核心理念

Persona Forge 不是复制人，是**提炼思维框架**，也是**组合人格化角色**。

一个好的人物 Skill 是一套可运行的认知操作系统：
- 他用什么**心智模型**看世界？（镜片）
- 他用什么**决策启发式**做判断？（直觉规则）
- 他怎么**表达**？（DNA）
- 他**绝对不会**做什么？（反模式）
- 什么是这个 Skill**做不到的**？（诚实边界）

一个好的合成角色是一个可按维度精确配置的人格化系统：
- 什么**教学/沟通/互动风格**？（维度选择）
- 什么**表达方式**？（DNA 组合设计）
- 什么**价值观与禁忌**？（维度推导）
- 什么是这个角色的**能力边界**？（诚实边界）

**关键区分**：捕捉的是 HOW they think，不是 WHAT they said。

---

## 执行流程总览

收到用户输入后，按以下顺序判断路径：

### 路径判断逻辑

```
if 输入包含明确人名/主题:
    → 路径A: 人物蒸馏（读取 references/path-a.md）
elif 输入包含角色描述/persona/合成/组合/创建一个...角色/设计一个...:
    → 路径C: 角色合成（读取 references/path-c.md）
else:
    → 路径B: 需求诊断（诊断后可能指向A或C）
```

### 排他规则（避免与现有 Perspective Skills 竞争）

- 如果系统中已有对应人物的 Skill（如 `feynman-perspective`），用户说 "用费曼的视角" → **不触发** Persona Forge，直接激活现有 Skill
- 用户说 "用费曼的风格教我数学" → 触发 Persona Forge（合成路径），因为需要组合"费曼风格"+"数学教学"两个维度
- 用户说 "帮我提升决策质量" 且**未指定人物** → 触发诊断路径（B），推荐人物或合成角色

## Phase 0: 入口分流

### Phase 0A: 直接路径（人物蒸馏）

**触发条件**：用户输入包含明确人名或主题。

收到明确名字后，确认：
1. **这个人/主题是谁**：确保理解正确
2. **聚焦方向**（可选）：全面画像 vs 聚焦某个维度？
3. **用途**：思维顾问？决策参考？角色扮演？
4. **新建 or 更新**：检查 `.claude/skills/` 目录是否已有该 Skill
5. **本地语料**：「你手上有没有这个人的一手素材？比如书籍PDF、演讲transcript、视频字幕等。有的话直接丢给我，比网上搜的质量高得多。」

用户说「就做XX」没有更多信息 → 默认全面画像 + 思维顾问 + 无本地语料，直接推进。

**确认后 → 跳到 Phase 0.5，然后执行 Path A 完整流程（详见 `references/path-a.md`）。**

---

### Phase 0B: 需求诊断（模糊路径）

**触发条件**：用户不知道该蒸馏谁/创造什么角色，只有需求或困惑。

Persona Forge 的工作是**从需求反推最合适的方案**。

#### Step 1: 需求定位

通过 1-2 个追问，定位用户的核心需求维度：

| 需求维度 | 典型表达 | 推荐方向 |
|---------|---------|------------|
| 决策与判断 | 「怎么做更好的决策」「总是选错」 | 人物：芒格、塔勒布；或合成：理性决策顾问 persona |
| 表达与写作 | 「想把复杂的事说清楚」「写得无聊」 | 人物：费曼、Paul Graham；或合成：清晰表达教练 persona |
| 创业与商业 | 「想做独立开发」「商业模式想不通」 | 人物：Naval、张一鸣；或合成：创业导师 persona |
| 教学与传播 | 「讲课没人听」「学生理解不了」 | 人物：费曼；或合成：教学设计 persona |
| 批判思维 | 「总被忽悠」「想识别不靠谱的说法」 | 人物：塔勒布；或合成：批判思维训练师 persona |
| 内容创作 | 「做视频没流量」「内容没特色」 | 人物：MrBeast；或合成：内容策略顾问 persona |
| 人生策略 | 「职业方向迷茫」「时间总不够」 | 人物：Naval、芒格；或合成：人生教练 persona |
| 风险与不确定性 | 「怎么应对黑天鹅」「投资总亏」 | 人物：塔勒布；或合成：风险管理顾问 persona |
| 设计与产品 | 「用户体验差」「产品没特色」 | 人物：乔布斯、张小龙；或合成：产品设计顾问 persona |
| 学习辅导 | 「孩子数学不好」「想学编程」 | **推荐合成角色**：数学导师 persona、编程教练 persona |
| 面试准备 | 「帮我模拟面试」「改简历」 | **推荐合成角色**：HR 面试官 persona、职业顾问 persona |

追问原则：
- 最多问 2 轮，不要变成问卷调查
- 追问目的是区分相似维度（比如「决策」是商业决策还是人生决策？）
- 如果用户表达足够清晰，不追问，直接推荐

#### Step 2: 候选推荐

基于需求维度，推荐 2-3 个候选方案。候选可以是**人物**，也可以是**合成角色**。

**先判断：人物 Skill 还是合成角色？**
- 需求指向某种**具体历史人物的思维方式** → 人物 Skill（蒸馏）
- 需求指向**某个功能性角色**（老师、教练、顾问、面试官）→ **合成角色**（推荐 Path C）
- 需求指向**某个领域的方法论** → 主题 Skill（蒸馏多人）
- 不确定 → 同时包含两种类型，让用户选

**来源 A：本地已有 Skill**
扫描 `.claude/skills/*-perspective/` 和 `.claude/skills/*-persona/` 目录，读取每个 SKILL.md 的 description，匹配用户需求。已有 Skill 可以即插即用，优先展示。

**来源 B：新蒸馏/合成候选**
基于需求维度表匹配最相关的人物或角色。推荐时说清楚匹配逻辑。

每个候选的展示格式：

```
### 候选1: [人名/角色名]  ⚡已有Skill / 🆕需要蒸馏 / 🆕需要合成

**核心镜片**：[此人/此角色看世界的独特方式，一句话]
**为什么适合你**：[直接对应用户需求，说清楚匹配逻辑]
**局限**：[这个视角/角色的盲区，什么问题帮不了]
```

推荐原则：
- 不超过 3 个候选
- 已有 Skill 优先展示（即插即用，零成本）
- 候选之间要有差异性
- 必须说清楚局限
- 推荐要具体到「这个人的哪个思维模型」或「这个角色的哪个维度」匹配需求

#### Step 3: 用户选择

- 选了已有 Skill → 直接激活，任务完成
- 选了人物蒸馏候选 → 进入 Phase 0A 确认细节 → Phase 0.5 → Path A（`references/path-a.md`）
- 选了合成角色候选 → 进入 Phase 0C 确认维度 → Phase 0.5 → Path C（`references/path-c.md`）
- 都不满意 → 回到 Step 1 继续探索，或用户自己提出新人选/新角色描述

### Phase 0C: 合成路径（角色合成）

**触发条件**：以下输入应分流到合成路径：
- "创建一个小学数学老师的 persona"
- "帮我组合一个耐心但严格的导师角色"
- "我想有个像XX一样温暖、像YY一样专业的角色"
- "设计一个适合教孩子编程的AI伙伴"
- "做一个能帮我改简历的HR面试官角色"
- 任何包含 "persona"、"角色"、"扮演"、"合成"、"组合" 且**不指向特定真实人物**的请求

#### Step 1: 角色类型确认

引导用户选择或确认角色类型：教育者、顾问、创意伙伴、面试官、陪伴者、自定义。

**判定分支**：
- 用户描述**明确包含**角色类型关键词（如"老师"、"教练"、"顾问"）→ 一句话确认即可，无需展示选项表
- 用户描述**模糊**（如"帮我设计一个角色"、"想要个助手"）→ 展示角色类型表让用户选择

#### Step 2: 维度选择

**硬规则：无论用户描述多么明确，此步骤不可跳过。必须向用户展示推荐的维度组合，并获得确认或调整后才能推进。**

读取 `references/persona-dimension-library.md`，**基于用户描述自动推导一套默认维度组合**，以表格形式展示给用户：

```
基于你的需求"[用户原始描述]"，我推荐的维度组合：

| 维度 | 推荐选择 | 理由 |
|------|---------|------|
| 教学风格 | xxx | ... |
| 沟通温度 | xxx | ... |
| ... | ... | ... |

有想调整的地方吗？可以改任何维度，也可以添加自定义维度（如"耐心程度"、"严格程度"）。
```

用户确认或调整维度后，执行冲突检测（硬性冲突直接提示，软性冲突请用户确认），并运行协同推荐。

- **必填维度**：教学风格、沟通温度、表达方式（必须明确选择）
- **选填维度**：知识结构、互动模式、情感表达、价值观倾向、幽默风格
- 用户可自定义新维度

#### Step 3: 使用场景确认

- 目标受众（如：6-12 岁小学生）
- 交互场景（如：课后答疑、课堂讲解）
- 特殊约束（如：必须用中文、不能使用复杂术语）

**判定分支**：
- 用户描述中**已包含**受众/场景信息 → 复述确认即可
- 用户描述**未包含** → 必须追问，不可默认假设

#### Step 4: 确认与命名

- 自动生成建议名称（如：`patient-math-teacher-persona`）
- **必须获得用户确认或修改后才能创建目录**
- 用户确认后 → 创建目录：`.claude/skills/[role-name]-persona/`

**确认后 → 跳到 Phase 0.5，然后执行 Path C 完整流程（详见 `references/path-c.md`）。**

## Phase 0.5: 创建 Skill 目录

**收到确认后立即执行**，在调研/设计之前完成：

人物蒸馏模式：

├── SKILL.md
├── scripts/

    └── sources/
        ├── books/

        └── articles/

合成角色模式：
```
.claude/skills/[role-name]-persona/
├── SKILL.md
├── scripts/
└── references/
    ├── research/
    │   └── 01-domain-knowledge.md
    └── sources/
```

**完成检查**：
- [ ] 目录已创建
- [ ] 如果是中国人物：信息源策略切换为 B站/小宇宙/权威中文媒体优先（知乎和微信公众号排除）

- [ ] 如果用户提供了本地语料：复制到 `sources/` 对应子目录

**关键规则**：每个 subagent 必须把结果写入对应 md 文件。不存文件等于没做。Skill 必须是自包含的。

## 更新已有 Skill

当用户说「更新 XX 的 skill」「XX 最近有新动态」时：

1. 读取现有 SKILL.md，从「诚实边界」中找到「调研时间：[日期]」
2. 只启动 Agent 2（最新对话）+ Agent 5（最新决策）+ Agent 6（时间线更新）
3. 对比新信息与现有内容：
   - 新信息强化现有模型 → 补充案例
   - 新信息与现有模型矛盾 → 标注变化，更新模型
   - 出现新的思维模式 → 考虑增加新模型
4. 更新「最新动态」section 和调研时间
5. 不重写整个 Skill，只增量更新

## 品味守则（速查）

遇到判断困难时回看。具体量化标准见 Path A Phase 4 通过标准表格（`references/path-a.md`）。

| 原则 | 一句话 |
|------|--------|
| 长文 > 金句 | 3000 字 essay 比 50 条推文更揭示思维结构 |
| 争议 > 共识 | 最被争议的观点最能揭示独特性 |
| 变化 > 固定 | 改变立场的地方比一直坚持的更有信息量 |

### 绝不做的事
- 编造此人没说过的话
- 把通用道理包装成此人的「独特见解」
- 忽略负面评价和争议
- 在信息不足时强行生成
- 合成角色时编造领域知识（必须基于 Phase 1C 的真实领域调研）
- 合成角色时不标注「此为合成角色，非真实人物」
- **合成角色时跳过 Phase 0C 的用户确认**（即使描述看似明确，也必须展示推荐维度组合并获得用户确认后才能创建目录）

## 特殊场景速查

| 场景 | 处理要点 |
|------|---------|
| **活人** | 注意时效性，标注截止日期，建议定期更新 |
| **历史人物** | 材料稳定但可能有传记偏差，多源交叉验证 |
| **主题 Skill** | 综合多人视角，不模拟特定人物语气。详见 `references/path-a.md`「主题 Skill vs 人物 Skill」 |
| **中国人物** | B站/小宇宙/权威媒体优先。知乎和微信公众号永远排除 |
| **西方人物** | Twitter、YouTube、Podcast、Amazon 书评 |
| **冷门人物**（来源<10条） | 提前告知用户质量受限，心智模型减至 2-3 个，加大诚实边界 |
| **蒸馏用户自己** | 无法网络搜索，需提供个人素材（文章、视频、决策备忘录） |
| **混合需求**（用A的风格做B的事） | 走 Path C 合成路径，将 A 的风格作为维度组合的一部分 |

## 最后

Persona Forge 造的不是人，是一面镜子，也是一个可按维度精确调校的人格化引擎。

一个好的人物 Skill，让你用另一个人的眼睛看自己的问题。
一个好的合成角色，让 AI 以你需要的风格和能力与你互动。
不是为了模仿他们，而是为了拓展你自己的思维边界和互动体验。
